3. Catalog Fidelity

Problem identified

The original runtime catalog also contained 160 rows, but those rows did not match the customer's authoritative 160 GLB keys. Equal row counts had obscured splitting, consolidation, and taxonomy differences.

Implementation

  • The Standard V1 CSV is converted one-to-one; rows are not split or consolidated.
  • ComparisonKey, prompt text, sort order, topic, benefit type, and source metadata are retained.
  • The converter rejects blank or duplicate keys and enforces the expected count of 160.
  • The deployed image identifies the catalog as glb-v1-standard-2026-07-31.
  • The original GLB prompts are serialized as JSON, preventing multiline text and pipe characters from corrupting prompt boundaries.
Verified deployment signal: the latest result begins with risk_benefits_life_insurance_benefit_offered, rather than an old custom key such as ret_prev.

4. Extraction Accuracy Improvements

The system prompt now makes extraction accuracy and completeness higher priority than alignment. It requires the model to:

  • treat every comparison key as an independent extraction task;
  • use only evidence applicable to the current benefit, population, option, unit, and period;
  • include all requested, supported characteristics rather than stopping at the first matching fact;
  • preserve market values together with their option, population, and denominator basis;
  • avoid calculating, reversing, rounding, combining, or inventing statistics; and
  • audit each result against its original GLB prompt before returning structured JSON.

Singapore interpretation layer

Country context is added dynamically for SGP. It recognizes equivalent local structures and terminology, including CPF, statutory versus supplementary benefits, and SGD limits, while explicitly prohibiting inference from general country knowledge when the supplied profiles do not contain evidence.

Run with bounded concurrency

Company and Market are not processed in separate calls. Each model call receives both the complete Company topic section and the complete Market topic section, together with up to 15 datapoint definitions. For example, 47 Healthcare datapoints are divided into 15 + 15 + 15 + 2, with the same complete Healthcare evidence supplied to every batch.

Batches execute in parallel under a semaphore to limit concurrency. After each response, requested keys are compared with raw structured output and parsed rows. Missing keys are retried once with the same full topic evidence and only the omitted datapoint definitions. Results are then deduplicated, validated, and restored to authoritative catalog order.

6. Alignment and Validation Improvements

  • Deterministic prevalence and percentile rules validate straightforward, like-for-like measures.
  • Comparability checks prevent direct numeric comparison across incompatible bases, such as annual versus per-birth limits.
  • Compound or qualitative provisions use evidence-grounded holistic alignment rather than the first number found.
  • Valid qualitative values such as unlimited or no overall maximum are not treated as numeric extraction failures.
  • Currency parsing recognizes SGD/S$ and HKD/HK$ forms.
  • Parent-child dependency rules, output formatting, and authoritative source ordering are enforced after aggregation.

Explicit negative normalization

A post-run review found that Not offered had been treated as an affirmative substantive value. The normalization was corrected and regression tested. Expected outcomes now include:

10. Known Limitation

Structural completeness does not guarantee factual correctness. In the latest run, the datapoint risk_benefits_disability_short_term_std_including_sick_leave_prevalence was returned with Market Practice Not Provided, although the Risk Benefits section explicitly states Short-Term Disability prevalence of 0.0%. Because the key was present, omitted-key retry did not activate.

This result is valid as a progress build and as evidence that missing-key handling works. It is not yet a final factual-accuracy benchmark.
