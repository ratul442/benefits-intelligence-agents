3. Workstream 1: Factual Extraction Accuracy

Customer findings

AreaObserved issueAcceptance criterion
EAPChildcare assistance, medical advice, and training returned Not Provided despite Wellbeing evidence.Each affected row contains the correct source-supported detail and is assigned to the correct datapoint.
HealthcareHospitalization maximum statistic was presented as applying to all peers.The result states that 95.8% applies to organizations with a maximum.
Business TravelSummary omitted the Company S$10M out-of-country medical maximum and Market S$300K median accidental-death benefit.Both measures appear with the correct party, benefit, unit, and basis.
MaternityIndividual service summaries omitted the shared Company S$5,000 annual maximum.Every affected individual-service row includes the shared annual maximum without applying it outside its source scope.

Diagnosis

  • Topic slicing is unlikely to be the primary cause because each batch receives the complete relevant Company and Market topic sections.
  • Structured parsing copies returned Company and Market strings and did not report dropped keys.
  • Existing retry handles absent keys only; it does not detect a present row with an incomplete value.
  • The strongest identified cause is model interpretation combined with earlier prompt competition: additional comments were de-prioritized, F4 encouraged compression, and shared or multiple measures were not explicit enough.

Implementation and verification

  1. Deploy prompt v3 with rules for additional comments, exact conditional denominators, multiple measures, shared limits, and concise-but-complete F4 output.
  2. Rerun GPT-5.6 Luna at low reasoning using the identical source files, catalog, batches, and concurrency.
  3. Compare all 160 rows against the finalized golden dataset by fact and source support, not text similarity.
  4. Classify the four known examples as Passed, Partially passed, or Failed, recording source evidence, golden value, and actual value.
  5. Repeat the stable configuration at least three times to assess consistency.

Conditional semantic audit

If v3 remains incomplete, introduce a targeted verification pass for complex or suspicious rows. The audit must receive the original datapoint prompt, full topic evidence, and initial value; return changes only when explicit evidence supports them; preserve the initial value otherwise; and report audited rows, recovered facts, tokens, and latency separately. It must not blindly retry every Not Provided value.

5. Workstream 3: Execution Performance and Parallelism

Current behavior

  • All 15 batch tasks are scheduled together.
  • An application semaphore permits at most nine active batch tasks, so 15 batches require at least two scheduling waves.
  • An omitted-key retry occurs inside the same bounded task and continues to occupy its concurrency slot.
  • processing_time_ms is application wall-clock time from before slicing through final aggregation.
  • Current per-topic timing is the sum of batch durations for that topic. Concurrent durations overlap and must not be added to derive wall-clock time.
  • The SSE endpoint sends an immediate status event, but usable rows and topic-complete events are emitted only after the full pipeline returns.
Interpretation of 36+ seconds: this is the current end-to-end application duration, not the sum of individual batch times. The customer's theoretical 12-second lower bound assumes all 15 calls execute concurrently without Azure-side queuing; the current application cap is nine.

Acceptance criteria

  • Batch timestamps demonstrate actual overlap and measured peak concurrency.
  • Phase durations reconcile with total wall-clock time within a documented tolerance.
  • Initial calls and retries are independently identifiable.
  • Token totals reconcile with the invocation-level total.
  • Azure throttling or queuing is reported as evidence, not inferred from latency alone.
  • Model comparison reports use the same telemetry schema.

8. Definition of Done

The iteration is complete when the selected configuration returns all 160 authoritative rows; satisfies the agreed factual accuracy and completeness threshold; resolves or explicitly flags the four known findings; produces reproducible timing, token, retry, and concurrency evidence; and has been compared fairly across the selected models. Alignment optimization should resume only after this factual gate is accepted.

This document defines the next iteration requirements and does not claim that locally implemented prompt v3 changes, semantic auditing, detailed telemetry, or controlled model benchmarks are already deployed or complete.
